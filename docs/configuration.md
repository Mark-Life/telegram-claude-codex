# Configuration

`.env` and `.env.local` are read from the repo root by `packages/env/src/bot.ts`. Real environment variables win over both. Missing or malformed required values fail at boot, not at first use.

Never put a comment on the same line as a value. The systemd unit loads `.env` as its `EnvironmentFile`, which keeps a trailing `# ...` as part of the value: `DEFAULT_TZ=Europe/Sofia  # my zone` stops the bot at boot. `.env.example` puts every comment on its own line above its key, so uncommenting a key line is safe.

| Variable | Required | Default | What it does |
| --- | --- | --- | --- |
| `BOT_TOKEN` | yes | — | BotFather token. Rejected when empty. |
| `ALLOWED_USER_ID` | yes | — | numeric Telegram user id of the owner. This one id is the only source of owner rights; it is never stored in the database and cannot be granted. |
| `GROQ_API_KEY` | yes | — | voice transcription. |
| `ELEVENLABS_API_KEY` | no | unset | [ElevenLabs](https://elevenlabs.io) key for voice replies: a run asked to answer by voice speaks its answer and sends it as a voice message (`send-voice-to-user.ts`). The voice and model are picked in `/settings` → Голосовые ответы. Unset, the run says voice is not set up and answers in text. Needs `ffmpeg` on the host. |
| `WORK_DIR` | no | unset | the single directory every run works in. Set it and there is no project switching: a stored project, a pinned topic and `PROJECTS_DIR` are all overruled. This is the normal deployment. |
| `PROJECTS_DIR` | no | `/home/agent/projects` | parent directory runs work under when `WORK_DIR` is unset. |
| `BWRAP_BIN` | no | `bwrap` on `PATH` | absolute path to bubblewrap, when it is not on the service's `PATH`. |
| `SOCAT_BIN` | no | `socat` on `PATH` | absolute path to socat, when it is not on the service's `PATH`. |
| `CODEX_BIN` | no | resolved at boot | absolute path to the `codex` CLI. Only needed when it is neither on the service's `PATH` nor in one of the user bin directories above. There is no variable that enables or disables a provider: an installed, logged-in CLI is enough. |
| `CODEX_TIER_MODELS` | no | the newest model of each tier the account offers | Codex slug per model tier, e.g. `luna=gpt-6-luna,terra=gpt-5.6-terra`. Unset, each tier runs on the first of its built-in candidates, newest first, that the account lists in `$CODEX_HOME/models_cache.json`: Astra `gpt-6.2-astra`, `gpt-6-astra`; Sol `gpt-6.2-sol`, `gpt-6.1-sol`, `gpt-6-sol`; Terra `gpt-6.1-terra`, `gpt-5.6-terra`; Luna `gpt-6-luna`. With no list, each tier takes its first candidate. When set it replaces the built-in candidates whole, one slug per tier. A tier left out is not offered and its picks move to the nearest tier given. So is a slug missing from the account's own list, and a tier none of whose candidates it lists: a ChatGPT Go login offers no Sol or Astra and only `gpt-5.6-terra`, so it gets Terra and Luna, and a stored pick of a missing slug moves to the nearest tier on the list. The judge uses the `luna` slug; light runs, the formatter and topic titles do too unless «Группы и гости» → Модель picks another tier (see [Settings](usage.md#settings)). An unknown tier or a malformed pair stops the bot at boot. |
| `CLAUDE_BIN` | no | the SDK's own binary | Claude Code binary runs spawn. An override moves with that install's own updates instead of the pinned SDK. It must be the native binary, best as an absolute path; a bare name is looked up on the service's `PATH`. A `.js` entry or a path that names nothing leaves Claude `unsupported`. |
| `PI_BIN` | no | resolved at boot | the `pi` CLI. Only needed when it is neither on the service's `PATH` nor in `~/.pi/agent/bin`, `~/.local/bin`, `~/bin` or `~/.bun/bin`. |
| `PI_DEFAULT_MODEL` | no | pi's `settings.json` default | the model pi answers on, as `provider/id` (`openrouter/z-ai/glm-5.2`). With neither this nor `defaultProvider`/`defaultModel` in `~/.pi/agent/settings.json`, pi reads `logged_out`. |
| `PI_LIGHT_MODEL` | no | `PI_DEFAULT_MODEL` | the model pi runs light runs (groups, guests, members, Business replies), topic titles, the format pass and the address judge's fallback on, as `provider/id`. A model picked in «Группы и гости» → Модель of `/settings` wins over it for light runs, titles and formatting, and one picked in «Служебные проходы» → Модель wins for its own pass. These runs get no provider key from the bot's env, so the provider needs its key in pi's `auth.json` or `models.json`; a model keyed only by the env (`GROQ_API_KEY`) is skipped and pi's default used. |
| `CLAUDE_TIER_MODELS` | no | from Claude Code's model list | Claude slug per model tier, same format as `CODEX_TIER_MODELS`. Unset, Luna, Terra, Sol and Astra are the full ids of the `haiku`, `sonnet`, `opus` and `fable` aliases. A slug the account does not offer is dropped with a warning. |
| `ANTHROPIC_API_KEY`, `CLAUDE_CODE_OAUTH_TOKEN` | no | unset | an API key or a long-lived token instead of `claude auth login`. A set token wins over the stored login. Not a Claude-only secret: every Claude child gets it, and a member's run can print it with `env`, as it can read the credentials file. Codex runs with full access (owner, executors, tasks) inherit it with the rest of the bot's env. |
| `CODEX_AUTO_COMPACT_TOKENS` | no | `150000` | context size, in tokens, past which Codex summarizes a session in place and carries on under the same session id. Anything but a positive integer falls back to the default. The Порог сжатия row of `/settings` → Провайдеры → Codex overrides it. |
| `DEFAULT_TZ` | no | `Europe/Sofia` | IANA zone a new reminder gets when the run names no other. Reminders in this zone are listed without a zone label. An unknown zone stops the bot at boot. The Часовой пояс row of `/settings` overrides it. |
| `MAX_CONCURRENT_RUNS` | no | `4` | agent runs allowed at once across every conversation and task fire, except those waiting on background work (`MAX_BACKGROUND_RUNS`). The Задач одновременно row of `/settings` overrides it. |
| `MAX_BACKGROUND_RUNS` | no | `20` | conversations and `prompt` task fires allowed to wait on background work at once, apart from `MAX_CONCURRENT_RUNS`; the turns their work starts later (a report, a wake-up, a message sent in) run here too. A waiting Claude process holds about 150–250 MB. |
| `EXECUTOR_MCP_URL` | no | unset | [Executor](https://executor.sh) MCP endpoint, wired into runs that are allowed it. v1 is `https://executor.sh/<org>/mcp`, v2 `https://mcp.executor.sh/org/<org>/mcp`. |
| `EXECUTOR_API_KEY` | no | unset | Executor key, sent as `Authorization: Bearer`: a v1 API key, or on v2 a personal access token (`exp_…`). It reaches Codex through its environment, never its command line, so other users on the host cannot read it from the process list. Claude never gets it: the bot calls Executor for it. |
| `EXECUTOR_VERSION` | no | `v2` for a URL on `mcp.executor.sh`, else `v1` | `v1` or `v2`: how script tasks are replayed. v1 posts them to Executor's REST `/api/executions`, v2 runs them through the MCP `execute` tool at `EXECUTOR_MCP_URL`. A self-hosted Executor sets it itself. Any other value stops the bot at boot. |
| `TYPESAFE_API_KEY` | no | unset | [TypeSafe](https://typesafe.ai) key for the four judgments the bot makes: which model a new conversation should run on, whether the call name was an address or a mention, whether a scheduled report really did its work, and whether a message asks for a reminder when the keyword scan missed it. Unset means Terra at medium effort for the first, a one-turn pass on the helper provider (Codex, Claude or pi, or the one picked in «Служебные проходы») for the second, and the other two skipped. |
| `TELEGRAM_API_ID` | no | unset | app id from [my.telegram.org](https://my.telegram.org), for the owner's own Telegram account. See [Telegram account](telegram-account.md). |
| `TELEGRAM_API_HASH` | no | unset | app hash from the same page. Set both or neither: only one of them stops the bot at boot. |
| `TELEGRAM_ACCOUNT_WRITES` | no | `confirm` | `confirm`: every action as the owner (a message, a file, a forward, an edit or delete, a reaction, a pin, a poll…) waits for the owner's button. `direct`: runs write at once, which is what lets a scheduled task send unattended; a write through the raw API tool `tg_call` still waits for the button. The Подтверждать действия аккаунта row of `/settings` overrides it. |
| `TELEGRAM_ACCOUNT_MCP_PORT` | no | `0` | loopback port the account tools listen on. `0` picks any free port at boot. |
| `API_ENABLED` | no | `false` | `true`, `yes`, `on`, `1` or `y` turns on the [HTTP API](http-api.md) inside the bot process. `false`, `no`, `off`, `0`, `n` or unset leaves it off and nothing listens. Any other value (`True` too) stops the bot at boot. |
| `API_PORT` | no | `8787` | the port the HTTP API listens on, always on `127.0.0.1`: a reverse proxy faces the internet. Read only with `API_ENABLED=true`. A port already in use leaves the API off and the bot running; the owner gets a message. |
| `API_PUBLIC_URL` | no | `http://127.0.0.1:<API_PORT>` | the `http(s)://` address clients reach the API at, through your proxy (`https://bot.example.com`). The OpenAPI document names it as its server, and `/apikeys` shows it. Setting it also tells the bot a proxy is in front, so the failed-key limit reads the client's address from the last `X-Forwarded-For` entry; unset, the header is ignored. A trailing `/` is dropped; anything but an http(s) URL stops the bot at boot. |
| `LOG_FORMAT` | no | `pretty` on a TTY, else `logfmt` | `pretty`, `logfmt` or `json`. Under systemd, leave it — `logfmt` is what journald wants. |
| `LOG_LEVEL` | no | `Info` | any Effect level: `All`, `Fatal`, `Error`, `Warn`, `Info`, `Debug`, `Trace`, `None`. |
| `TG_LOG_FILE` | no | `events.jsonl` | the run ledger (also access changes, API keys and API writes). A relative path resolves inside `.data/`. |
| `OTEL_EXPORTER_OTLP_ENDPOINT` | no | unset | also send logs (run events included) and traces to an OTel backend. The local ledger is always written. |
| `OTEL_EXPORTER_OTLP_HEADERS` | no | unset | `k1=v1,k2=v2` auth headers for the endpoint above. |

Executor needs both of its variables before it activates; a blank string counts as unset.

**The Executor values must be yours.** `EXECUTOR_MCP_URL` is scoped to one organisation and `EXECUTOR_API_KEY` authenticates as it — an agent run reaches whatever that organisation has connected (Notion, GitHub, Vercel, and so on). Mint a key in your own Executor dashboard for this machine. Never copy the pair out of someone else's `.env` or another deployment: you would be handing a bot to a stranger's integrations, and revoking the key later breaks both machines.

`TYPESAFE_API_KEY` is per machine as well, and nothing breaks without it: the address judge falls back to a one-turn pass on the helper provider (Codex, Claude or pi, or the one picked in «Служебные проходы»), and the two extra checks are simply skipped — the bot behaves exactly as it did before them. Mint the key at [typesafe.ai](https://typesafe.ai); one judgment costs 550–900 input tokens.
